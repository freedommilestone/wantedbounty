# Next.js migration

All five public pages are now App Router routes under `src/app/`. Their existing interactive React components remain client components, with static initial HTML generated by Next.js. The shared root layout keeps the wallet provider alive across navigation. Internal navigation uses `next/link`; the custom browser-history router and Vite entrypoint are removed.

All global styles are imported once in `src/styles.css` to keep their order consistent across direct visits and client navigation. Existing browser-only initial state for Explore and saved orders is restored in effects after hydration.

The existing Node handlers moved to `server/handlers/`, with Next.js API route wrappers under `src/pages/api/`. Keeping the Node request/response contract preserves existing tested order/payment behavior. The poster route allows 2 MB JSON bodies and sets maxDuration to 300 seconds. Secrets remain only in server modules; the compatibility config exposes only the three explicitly public legacy Vite settings.

Vercel configuration selects Next.js, `npm run build`, and `.next`; the old index.html rewrite is removed. Existing production secrets do not need renaming. A deployment and live endpoint smoke check are still required after publication. No real paid image generation is performed in local verification.

Official references used:
- [Next.js Vite migration guide](https://nextjs.org/docs/app/guides/migrating/from-vite)
- [API route request and configuration behavior](https://nextjs.org/docs/pages/building-your-application/routing/api-routes)
- [Server and public environment variables](https://nextjs.org/docs/app/guides/environment-variables)

## Validation

- Production build and all 38 existing payment/order tests pass.
- All five routes load in Chrome at phone and desktop widths without browser errors or horizontal overflow.
- How It Works checked at 320, 390, 599, 600, 768, 1024, 1100, 1101, 1280, 1536 and 1920 pixels. Resizing the same page preserves the same six card elements while switching between one, two and three columns.
- Mocked Phantom connection survives client navigation without reconnecting; saved order recovery restores after hydration and disables another payment for an order in review.
- Local API routes return expected method errors; a 1.2 MB JSON request reaches the poster handler and a 2.2 MB request is rejected by its parser.
- The development server compiles and serves How It Works successfully with Turbopack.
- No payment was sent and no billable poster was generated.
