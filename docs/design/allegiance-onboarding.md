# Allegiance onboarding

`/allegiance` is a single responsive Next.js page with three native radio cards. Desktop uses three columns; narrow screens use one column. Current Wanted Bounty branding and shared navigation are retained. Selection is saved only on confirmation. Successful confirmation opens `/dashboard`; existing players skip the chooser and sign in directly to their dashboard. Confirmed allegiance is permanent, enforced by a database trigger. Authentication confirmation returns to `/account`, preserving the configured Supabase redirect URL. Password recovery is exempt from the onboarding redirect.

`public.players` holds the Auth user ID, display name, bio, allegiance, selection timestamp, and creation/update timestamps. Signup triggers create the record; Auth metadata changes sync display-only name/bio. RLS limits reads and updates to the owning user. The browser can update only the allegiance column, and only an initial null choice can change to a faction; later changes and clearing the choice are rejected. See `player-dashboard.md` for the follow-up migration and server-owned game state. Passwords and login credentials remain managed by Supabase Auth. No email or password is copied to this table.

Migration: `supabase/migrations/20261105215819_player_allegiance.sql` (applied to the connected Supabase project). Transactional verification: `supabase/tests/player_allegiance.sql`; test accounts are rolled back. Existing users are backfilled without an allegiance and choose on their next profile visit.

Separate generated assets: `public/scene/allegiance-flags-v1.webp`, `public/scene/allegiance-coast-v1.webp`, `public/scene/allegiance-card-v1.webp`. Generated with the built-in image generation tool using the user's `03_Choose_Faction.png` as reference. Encoded to WebP for delivery, preserving transparency. Text and controls are live HTML, never baked into the background.
